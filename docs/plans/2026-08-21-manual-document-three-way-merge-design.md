# Markdown 文档手动刷新与冲突解决设计

## 目标

将现有“从磁盘重新载入”收敛为可靠的手动同步：只有用户点击刷新时才读取磁盘最新内容，不增加实时文件监听。刷新使用打开文档时保存的原始文本、YKMarkdown 当前文本和磁盘最新文本进行三方合并。

没有重叠的内外部修改自动合并；双方修改同一部分时进入专用冲突模式。冲突信息只存在于应用内，不向 Markdown 写入 `<<<<<<<`、`=======`、`>>>>>>>` 等标记。

## 范围

第一版包含：

- 打开或切换文档时保存内存原始快照。
- 点击刷新时读取 UTF-8 磁盘内容并执行行级三方合并。
- 自动合并互不重叠的修改。
- 以红色本地内容、绿色磁盘内容展示重叠修改，并高亮行内差异。
- 冲突期间只显示源码冲突解决界面。
- 显示未解决冲突数，并支持跳到下一个冲突。
- 每处冲突支持保留当前、使用外部、两者保留和手动编辑。
- 全部解决后一次性应用合并结果。

第一版不包含实时监听、磁盘快照缓存文件、Markdown 语法级合并、自动选择冲突一侧、多人协作或可视化历史记录。

## 三份文本与基准语义

- `base`：当前文件最近一次确认的磁盘内容。首次打开时等于打开得到的文档文本。
- `local`：点击刷新时 YKMarkdown 内的当前文本，可能包含未保存修改。
- `remote`：本次点击刷新后从 `fileURL` 重新读取的磁盘文本。

刷新判断：

1. `remote == local`：无需修改文档，只把磁盘基准更新为 `remote`。
2. `remote == base`：磁盘没有新变化，保留 `local`。
3. `local == base`：只有磁盘变化，直接载入 `remote`。
4. 三者都不同：执行三方合并。

合并完成后，`lastKnownDiskText` 必须更新为 `remote`，而不是合并结果。合并结果仍可能包含尚未保存的本地修改；把它误当作磁盘基准会影响下一次刷新判断。

## 合并模型

新增纯 Swift 的 `DocumentThreeWayMerge`。它先将文本拆成保留换行符的行，再分别计算 `base -> local` 和 `base -> remote` 的变更区间。

- 两侧变更区间不相交：按原始顺序同时应用。
- 两侧得到相同替换文本：只应用一次。
- 只有一侧修改某一区间：应用该侧修改。
- 两侧变更区间重叠且结果不同：生成一个结构化冲突。

输出由普通文本片段和冲突片段按顺序组成。冲突片段包含稳定 ID、本地候选文本、磁盘候选文本和用于行内着色的差异范围。冲突未全部解决前，不修改 `document.text`，因此取消本次合并不会破坏用户当前内容。

行级合并保证 Markdown 原文不经过解析或重新序列化，避免顺手改变列表、表格、代码块和空行格式。行内差异只用于展示，不参与合并决策。

## 冲突模式

检测到冲突后保存进入前的布局，显示专用源码合并界面：

- 隐藏目录和 Markdown 预览。
- 暂时禁用普通布局切换和搜索，避免针对尚未落盘的临时合并内容进行导航。
- 顶部固定显示“还有 N 个冲突未解决”和“下一个冲突”。
- 普通片段使用等宽字体展示。
- 每个冲突块上方使用浅红背景显示 YKMarkdown 当前内容，下方使用浅绿背景显示磁盘内容；具体变化字符使用更深的同色背景。
- “下一个冲突”滚动到当前冲突之后的下一处，末尾循环到第一处，并把键盘焦点交给目标冲突块。

每个冲突块提供四种处理：

- `保留当前`：使用本地候选文本。
- `使用外部`：使用磁盘候选文本。
- `两者保留`：按本地在前、磁盘在后的顺序拼接。
- `手动编辑`：将该冲突切换为普通等宽文本编辑区，初始值使用本地候选文本；用户点击“完成此处”后才视为解决。

解决一处后计数立即减少。已解决冲突不再显示红绿候选，而显示最终普通文本，并允许重新编辑。计数为零时显示“完成合并”；点击后将所有片段拼成最终 Markdown、赋给 `document.text`、把磁盘基准更新为本次 `remote`，然后恢复进入冲突前的布局。

用户可以随时取消合并。取消后保留刷新前的 `local`，丢弃本次临时合并会话，不修改磁盘基准。

## 错误与边界

- 未保存文档没有 `fileURL`，刷新按钮保持禁用。
- 文件读取失败时保留当前内容并显示现有错误提示。
- 空文件、末行没有换行符、CRLF 和 Unicode 字符必须保持可比较且不造成范围越界。
- 连续插入、删除与替换需要合并成稳定的变更区间。
- 同一位置双方插入不同文本视为冲突；插入相同文本只保留一份。
- 合并会话期间再次刷新不启动第二个会话。
- 完成合并只修改内存文档，是否保存仍遵循系统文档窗口原有行为。

## 验收标准

- 仅磁盘修改时，点击刷新后立即显示磁盘最新内容。
- 仅 YKMarkdown 修改时，点击刷新不丢失当前内容。
- 双方修改不同段落时，点击刷新后自动得到两边修改，且不出现冲突界面。
- 双方修改同一行时，只显示源码冲突模式，红色和绿色候选与行内变化清晰可辨。
- “下一个冲突”可以循环定位；未解决数量随处理实时减少。
- 四种处理方式生成预期文本；全部解决前不会改写 `document.text`。
- 完成后恢复原布局；取消后恢复刷新前内容。

# 共享行间距设计

## 目标

为 Markdown 源码编辑器和可编辑预览增加一个共享的行间距设置。用户只需调整一次，两侧便同步收紧或放宽；设置跨窗口持久化，调整过程不应重载预览或破坏滚动位置、选区和编辑焦点。

## 方案选择

候选方案包括：让源码与预览使用同一绝对行高、提供“紧凑/标准/宽松”离散预设，以及在各自基础行高上应用共享疏密倍率。采用第三种方案。

源码使用等宽字体，现有基础行高倍数为 `1.55`；预览使用宋体，现有 CSS 行高为 `1.9`。强制使用同一绝对值会改变其中一侧的默认观感，也无法兼顾不同字体。共享倍率既能保留当前排版，又能让两侧的疏密变化保持一致。

## 交互与数据流

设置页“排版”区域新增“行间距”滑杆，范围为 80%–130%，步长为 5%，默认值为 100%。数值通过 `AppStorage` 保存，作为所有文档窗口的共享偏好。

`EditorView` 读取倍率并分别传给 `MarkdownSourceEditor` 与 `MarkdownPreviewView`。源码编辑器把倍率纳入外观签名，只在倍率或其他外观参数变化时重新设置段落样式和输入属性，实际行高为 `1.55 × 倍率`。预览初始 HTML 把 `1.9 × 倍率` 写入 CSS 变量；运行时通过 `window.setLineSpacing` 更新该变量，不重新加载 WebView。

## 边界与验证

倍率模型集中定义存储键、默认值、上下界、步长和换算方法，避免 SwiftUI、AppKit 与 HTML renderer 各自复制数值。设置滑杆自身限制正常输入，换算方法仍执行钳制，以兼容旧偏好或手工写入的越界值。

单元测试覆盖默认值、边界钳制、源码与预览行高换算、HTML 初始 CSS 和实时 JavaScript API。最后运行目标测试与 macOS 构建，并用 `git diff --check` 检查变更。
